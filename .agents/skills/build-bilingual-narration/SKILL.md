# 双语语音素材制作

把课程文本变成与界面一致、可离线播放的录音。保留现有素材 ID、语言切换和播放取消行为；按用户要求处理受影响的语言和内容。

## 定位真实声源

在包含 `package.json`、`src/` 和 `scripts/` 的项目根执行命令。下面链接相对于当前 skill；迁移到其他项目时，先定位对应的课程、播放器和生成器，不能假定此目录结构仍存在。

| 入口                                                                                                                         | 用途                                                              |
| ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| [生成器](../../../scripts/generate-audio.py)                                                                                 | 参数、声线默认值、合成、响度处理、暂存与发布的唯一实现            |
| [依赖](../../../scripts/requirements-audio.txt)                                                                              | 固定合成客户端版本；安装环境见根目录 [README](../../../README.md) |
| [课程](../../../src/data/curriculum.ts)、[翻译](../../../src/data/localization.ts)、[题目生成](../../../src/lib/learning.ts) | 实际词语及各阶段题干；生成器直接读取这些内容                      |
| [播放器](../../../src/lib/audio.ts)                                                                                          | 本地 MP3 优先、设备语音兜底、取消与超时逻辑                       |
| [资源测试](../../../tests/audio.test.ts)                                                                                     | 文本覆盖、文件哈希、大小、时长与播放行为                          |

先区分录音听感与播放故障。正常路径播放本地 MP3；播放器中的设备语音 `rate`、`pitch` 只影响兜底，调它们不会改变已有录音。若录音加载失败导致退回系统声线，先修复资源或缓存问题。

## 声线与样例

- 用户已有声线、语言或语速偏好时沿用。当前项目推荐英文 Jenny、普通话 Xiaoxiao，分别稍放慢语速，并保留自然音高；这是默认选择，不是所有教育产品的强制要求。
- 声线尚未确定或用户明确反馈听感时，先用少量真实单词、长题干和鼓励语制作样例，覆盖极短词与长句。样例写到临时目录或文档预览目录，不先覆盖发布素材。
- 当前生成器没有“仅生成若干 ID”的 CLI 参数。需要小样时使用相同引擎单独合成，不虚构 `--sample` 或 `--ids` 参数。
- 可以交付样例供用户试听，但不把再次确认当成每次更新的前置条件。已有推荐授权时继续完成任务。区分合成女声与真人录音；没有实际听到音频时，不声称已逐条试听。

## 生成与恢复

先确认当前 Python 能加载所需依赖，且 `ffmpeg`、`ffprobe`、Node 可用。缺少依赖时按 README 建立独立环境；下列 `python3` 指已准备好的解释器。

只运行受影响的语言；两种语言都要更新时依次或适度并发运行：

```bash
python3 scripts/generate-audio.py --language en --jobs 2
python3 scripts/generate-audio.py --language zh --jobs 2
```

更换声线或语速使用实际支持的参数，例如 `--voice en-US-JennyNeural --rate=-10%`。用 `--help` 核对当前接口；通常不需要 `--force`。

当前 CLI 没有响度目标或仅后处理参数。先测量实际发布文件，排除旧缓存；若已有校正仍不符合要求，需要修改现有校正策略及配置指纹。原样重跑只会复用文件，`--force` 也不能代替新的音量策略。

生成时需要联网把课程文案送给合成服务；运行中的 App 仍播放本地文件。不要为了换声把客户端改成依赖在线语音 API。

保持生成器已有的关键约束：

- 文案从课程生成，不手工维护第二份词表，也不直接编辑 `src/lib/audio-manifest*.ts` 生成文件。
- 引擎、声线、语速、音高、处理方式一起参与配置指纹；文本参与缓存键，公开文件用哈希检查。修改后处理却复用旧配置，会让换声或调音没有生效。
- 修改 `correct_loudness()` 等后处理实现时，同步更新 profile 的 `loudnessCorrection` 版本标记；只改函数代码不会自动改变缓存指纹。仅调整后处理且合成参数不变时，优先复用生成器匹配的中间素材。
- `.audio-cache/` 保存中间结果。先完成一套语言的生成和检查，再逐文件原子替换，最后写完整清单。两种语言各自发布；不是跨语言或整目录事务。需要双语一起交付时，两边完成后再构建。
- 服务请求有有限重试。连续失败后停止发布，保留有效暂存文件，修复原因后重跑；不要无限重试或悄悄混入系统默认声线。
- `--engine macos` 是维护时明确选择的后备方案，不是神经语音失败后的自动切换。

## 音量与时长

复用生成器处理，不在 skill 内另复制一套 FFmpeg 实现。尤其保留以下经验：

- 只裁剪首尾静音，保留句中停顿，避免用升调或重采样伪造童声。
- 单遍响度标准化对“一”“鹿”这样的极短词可能偏响。测量编码后的文件，再以固定增益校正；不足测量窗口的短词用保守 RMS 兜底。
- 当前目标约 -18 LUFS，真峰值不高于 -2 dBTP。峰值约束优先，因此部分录音会略轻；不要声称每条录音响度完全相同。
- 当前播放器总时限为 15 秒，生成器把单条限制在 0.2–12 秒，预留加载时间。迁移项目或改语速时重新核对两者，超长题干优先精简或合理调整语速，不截断内容来通过检查。

## 验收与交付

生成完成后检查两种清单与实际文件一致，词语、三个年龄段题干和反馈均有录音。数量从当前课程及生成器推导，不沿用某次交付的固定总数。

```bash
npm test
npm run build
npx playwright test tests/e2e/language.spec.ts tests/e2e/offline.spec.ts
```

声音更新通常用这些检查即可；若同时改播放器交互，再选择相关学习流程测试。检查通过后不无理由重复整套测试。

对有代表性的短词、长句测量响度、峰值和时长，并提供来自实际发布文件的试听。自动化验证能确认资源与播放行为，不能替代用户对音色的偏好。

生产 Service Worker 按素材内容换版本；开发服务不安装离线包。旧页面显示“离线已准备好”可能仍指旧缓存，需要确认新版本已安装；不得以清空用户学习进度作为更新声音的办法。报告声线、处理范围、真实检查结果和试听位置；提交、推送或部署按当前用户请求执行。
